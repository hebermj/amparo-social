# Busca sempre + curadoria pela IA (substitui o fallback do ADR-0004)

Quando o usuário faz um Pedido de Atividade, o sistema **sempre** dispara a Busca Web (não só quando a Base tem < 3 resultados, como no ADR-0004). O webhook detecta o pedido por **heurística** (`parecePedidoDeAtividades`), não por marcador da LLM — os marcadores `[[RECOMENDAR:]]`/`[[BUSCAR:]]` foram aposentados; restam só `[[PERFIL:]]`/`[[HORARIO:]]` (marcadores de atividade removidos do prompt e do ADR-0003). O termo de busca combina palavras-chave da mensagem com o perfil e a cidade (ampliando para outros bairros quando a região do usuário não atende). A IA recebe a fusão Base de Atividades + Resultados da Busca (com `origem` marcada, preferindo a Base), **cura** as relevantes e escreve a mensagem final (máx. 2 parágrafos, sem URLs cruas, com rótulo de fonte). Se a curadoria falhar ou vazar URL crua, cai no template. Cache de resultados brutos na sessão por 1h serve o template direto (pula busca e curadoria); rate-limit de 10 buscas explícitas/hora/sessão cai para a Base curada. Motivação: os modelos gratuitos ficam fortemente rate-limited, então o caminho de atividade precisa funcionar mesmo quando a LLM de chat falha, e o usuário idoso nunca deve receber a mensagem de erro crua.
